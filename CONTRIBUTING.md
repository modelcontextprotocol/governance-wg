# Contributing

We welcome contributions from anyone interested in refining, documenting, and stewarding MCP's governance processes and community values!

## Quick Start

1. **Join the community** — Connect on the `#governance-wg` channel in [MCP Discord](https://discord.com/invite/6CSzBmMkjX)
2. **Understand the scope** — Review the [README](./README.md) and the [charter](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/community/working-groups/governance.mdx)
3. **Start contributing** — Attend the monthly working session, open issues, or submit PRs

## Ways to Contribute

### Participate in Discussions

- Join the monthly working session (no approval needed!)
- Engage in Discord conversations
- Comment on GitHub issues and PRs
- Share your experiences with MCP governance and community processes

### Submit Proposals

Have an idea for improving MCP's governance processes or community values? We'd love to hear it!

1. **Open an issue** to discuss the idea first
2. **Draft a proposal** under `proposals/`
3. **Submit a PR** for community review
4. **Iterate** based on feedback

### Improve Documentation

- Fix typos or clarify existing governance docs
- Add examples or guides
- Document edge cases or gotchas

### Review and Provide Feedback

- Review open PRs
- Test proposed changes against real community experience
- Share implementation feedback

## Proposal Development

When developing proposals:

1. **Propose first** — Open an issue to discuss before writing a full proposal
2. **Follow MCP standards** — Align with existing MCP conventions, governance docs, and the working and interest groups model
3. **Document thoroughly** — Include rationale, examples, and edge cases
4. **Consider breadth** — Think about applicability across WGs, IGs, and the wider community

## Changing Governance Documentation

The charter draws a narrow line between editorial and substantive changes:

- **Editorial revisions** — typos, clarifications, broken-link fixes, and rewordings that do not change meaning. These may land autonomously with documented rationale.
- **Substantive revisions** — anything that changes the meaning, scope, or applicability of an existing rule. These require WG consensus, followed by Core Maintainer approval.
- **Pages owned outside this WG** — propose the change to that owner; the owner decides.

## Promoting Proposals

For proposals that affect project-wide governance:

1. **Gather community experience** — Get real-world validation
2. **Present to the working group** — Build consensus and support
3. **Coordinate with Core Maintainers** — Work with the WG's Lead and sponsors
4. **Record the decision** — Capture the outcome in meeting notes or GitHub

Protocol changes are out of scope for this WG. They go through the [SEP process](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/community/sep-guidelines.mdx) and the relevant spec-producing Working Group.

## Guidelines

### Code of Conduct

All participants must follow the [MCP Code of Conduct](https://github.com/modelcontextprotocol/.github/blob/main/CODE_OF_CONDUCT.md).

### Antitrust Compliance

Per the [MCP Antitrust Policy](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/ANTITRUST.md), discussions must focus on:

- Technical standards and specifications
- Open collaboration

And must avoid:

- Pricing, costs, or margins
- Customer lists or strategies
- Competitive information

## Recognition

Active contributors — those who attend 2+ sessions or make substantive contributions — can be recognized in [GOVERNANCE.md](./GOVERNANCE.md). Self-nomination is welcome!

Sustained participation over 3 months, meaningful contributions, and nomination by an existing WG Member or Lead are the path to WG Membership. See [GOVERNANCE.md](./GOVERNANCE.md) for details.

## Communication Channels

| Channel | Purpose |
|---------|---------|
| Discord `#governance-wg` | Real-time discussion and Q&A |
| GitHub Issues | Proposals, bugs, and feature requests |
| GitHub Discussions | Longer-form conversations and meeting notes |
| Monthly Working Session | Synchronous collaboration and decisions |

## Getting Help

- **Discord:** Ask in `#governance-wg`
- **GitHub Issues:** Open an issue with your question
- **Meetings:** Bring questions to the monthly working session
- **Leads and Members:** Reach out to the people listed in [GOVERNANCE.md](./GOVERNANCE.md)

We're here to help — don't hesitate to ask!
